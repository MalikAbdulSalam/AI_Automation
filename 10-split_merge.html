Split → Process → Merge

📘 Notes on the core n8n nodes that power scalable, resilient automation.

This pattern is a fundamental workflow architecture in n8n, especially when dealing with complex or voluminous data. The core idea is to break down a large or complex data set into manageable pieces, perform an action on each piece, and then recombine the results.

1. Split (Loop Over Items / Split Out)

The first step involves separating your data into individual items for processing. In n8n, two main nodes handle this:

🔁 Loop Over Items (Split in Batches)

This node is used to break a list of items into smaller, manageable batches. This is particularly useful for avoiding API rate limits or processing a large dataset in chunks. You define a Batch Size to control how many items are passed through the loop in each iteration.

📌 Use Case: If you have 100 records to update in an external system that limits requests to 10 per minute, you can set the Batch Size to 10. This node will output 10 items at a time, allowing you to insert a Wait node to respect the rate limit.

Key Context: The node provides a currentRunIndex (the number of the current batch) and a noItemsLeft (a boolean indicating if all items are processed) in its context, which you can use for advanced logic.

🔀 Split Out (Item Lists Node)

This node is used to handle nested data, where a single item contains an array within it.

📌 Use Case: Imagine you have an API response for an invoice that contains a list of charges. n8n sees this as one item. By using "Split Out" on the charges field, you can create a separate item for each individual charge, allowing you to process each one (e.g., calculate its total).

Best Practice: When using Split Out, remember to include fields from the parent item (like invoice_id) so the context isn't lost after the split.

ℹ️ Note: n8n automatically processes each item for many nodes; however, specific nodes like RSS Feed Read process only the first item. In these cases, a Split node is essential to force the workflow to handle each input separately.

2. Process

This is the core of the workflow, where you perform your automation logic on each split item. Since the data is now broken down into individual items, you can connect almost any node to act upon them.

⚙️ Common Actions

This could be an HTTP Request to send data to an API, an Edit Fields node to transform the data, an If node to filter or route items, or a Code node for complex custom logic.

🧠 The Logic: n8n will execute the "Process" part of your workflow once for every item that comes out of the "Split" stage. For example, if you split out 20 charges, a subsequent HTTP Request node will be called 20 times — once for each charge.

3. Merge

After all items have been processed, the Merge node recombines the data streams. It takes multiple inputs and combines them into a single output.

📎 Append

Keeps data from all inputs, outputting the items from each input one after another.

🔗 Combine (by Position)

Merges items based on their order (e.g., the first item from Input 1 merges with the first from Input 2).

🔑 Combine (by Matching Fields)

Merges data by matching values in specified fields. This operates like an SQL Join.

  • Output Types: You can choose to keep matches (inner join), non-matches, everything (outer join), or to enrich one input with data from the other (left/right join).
🧾 SQL Query

Allows you to write a custom SQL statement to merge the data from multiple inputs for advanced combinations.

📦 Aggregate (Item Lists)

This is the counterpart to "Split Out". It takes many processed items and groups them back together into a single item, effectively reversing the split process.

📊 Summarize (Item Lists)

Rather than merging all the raw data, this node computes statistics (like sums, averages, or counts) across the processed items, functioning like a pivot table.

Pattern in Practice

A common and powerful example of this pattern is processing a list of invoices:

🧾 Invoice Processing Workflow
  • Split: You receive an API response with multiple invoices. Use Loop Over Items to iterate through the list one by one.
  • Process: For each invoice, you might use an HTTP Request to call a "mark as paid" endpoint on a payment gateway.
  • Merge: After all invoices are processed, you can use the Merge (or Aggregate) node to combine the success/failure responses from all the API calls into a final single report item.
🚀 Why This Pattern Matters
This "Split, Process, Merge" architecture gives you fine-grained control over how your workflow handles data, making it more robust and scalable for complex automation tasks.
