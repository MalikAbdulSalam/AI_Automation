n8n Workflow Automation

Complete Course Guide — From Triggers to AI-Powered Workflows

Part 1: Foundation & Core Concepts

What is n8n? An open-source, low-code platform for automating tasks by connecting apps, services, and APIs.

Key Concepts

  • Workflow – The entire automation pipeline.
  • Node – A single step in the workflow (trigger, action, transformation).
  • Trigger – The event that starts the workflow.
  • Data Flow – How data moves from one node to the next via JSON.
Teaching Tip: Start with a simple two-node workflow (Trigger → Node) so students see immediate results. Then gradually add complexity.

⚡ Triggers – How Workflows Start

Every workflow begins with a trigger. Here are the three most common types:

1. Webhook Trigger

Analogy: A doorbell. An external event rings the bell, and the workflow answers.

  • Provides a unique URL that listens for HTTP requests (GET, POST, etc.).
  • Ideal for real-time integrations (e.g., "When I receive a payment, update my CRM").

2. Schedule Trigger

Analogy: An alarm clock. The workflow runs automatically at a set time.

  • Runs on a fixed interval (every 5 minutes, every day at 9 AM, etc.).
  • Perfect for recurring tasks like daily report generation.

3. Form Trigger

Analogy: A suggestion box. A person fills out a form, and the workflow starts.

  • Generates a hosted form with custom fields (text, dropdowns, file uploads).
  • Great for collecting structured data from users.
Pro Tip: When testing, start with a Manual Trigger to quickly run the workflow, then swap it with your real trigger once the logic is solid.

Conditional Logic – If & Switch Nodes

These nodes make your workflows "smart" by enabling decisions and routing.

The If Node – The "Yes/No" Decision Maker

  • Evaluates a condition and splits data into two paths: true and false.
  • Configuration: Value1 [Operation] Value2.
  • Example: If orderStatus equals "processing" → send to processing branch; else → send to completed branch.

The Switch Node – The "Multi-Branch Router"

  • Routes data to one of many outputs (3+ branches).
  • Each rule defines a condition; unmatched items go to the Fallback output.
  • Example: Route customer support tickets by issue type: billing, technical, general, fallback.
Rule of Thumb: Use If for simple true/false checks. Use Switch when you have 3+ distinct routes.

✏️ Data Transformation – The Edit Fields Node

After routing data, you often need to reshape it for the next step. The Edit Fields node is your data studio.

Key Features

  • Manual Mapping: Drag and drop fields from the Input panel to create or overwrite fields.
  • Expressions: Use {{ $json.fieldName }} to pull live data from previous nodes.
  • Keep Only Set Fields: Discard all original data and only output the fields you define — great for privacy and performance.

Example: Cleaning Data

Input: { "firstName": "John", "lastName": "Doe" }

Using an expression: {{ $json.firstName + " " + $json.lastName }} → output: { "fullName": "John Doe" }

Real-World Scenarios

Scenario 1: Customer Support Ticket Triage

Goal: Automatically categorize and route support tickets, then format them for the helpdesk system.

Form Trigger → If (VIP Check) → Switch (Issue Type) → Edit Fields (Clean Data) → HTTP Request (Send to Helpdesk)

Step 1: Trigger Data

{ "customerName": "John Doe", "email": "john@email.com", "issueType": "billing", "issueDescription": "I was charged twice", "isVIP": "true" }

Step 2: If Node – Priority Check

  • Rule: If isVIP equals "true" → High Priority
  • Else → Normal Priority
  • Output adds a priority field.

Step 3: Switch Node – Route by Issue

  • Rule 1: If issueType = "billing" → Billing Team
  • Rule 2: If issueType = "technical" → Tech Support
  • Rule 3: If issueType = "general" → General Support
  • Fallback: Unassigned Queue (manual review)

Step 4: Edit Fields – Clean for Helpdesk

{ "ticketTitle": "billing", "ticketDescription": "Customer: John Doe\nIssue: I was charged twice\nPriority: High", "customerEmail": "john@email.com", "assignedTo": "support@billing.com", "timestamp": "2026-07-01T10:30:00.000Z" }

Scenario 2: E-commerce Order Fulfillment

Goal: Process incoming orders, check for express eligibility, route to the correct fulfillment center, and format data for the warehouse.

Webhook Trigger → If (Express Check) → Switch (Region) → Edit Fields (Warehouse Format) → HTTP Request (Send to Fulfillment)

Step 1: Trigger Data

{ "orderId": "ORD-12345", "customerName": "Maria Garcia", "totalAmount": 1250, "shippingAddress": { "country": "US", "city": "New York" }, "shippingMethod": "standard" }

Step 2: If Node – Express Eligibility

  • Rule 1: If totalAmount > 1000 → Express (FREE)
  • Rule 2: If shippingMethod = "express" → Express (PAID)
  • Else → Standard Shipping

Step 3: Switch Node – Fulfillment Center

  • Rule 1: If country = "US" → US Center
  • Rule 2: If country in ["UK","DE","FR"] → Europe Center
  • Rule 3: If country in ["JP","CN","IN"] → Asia Center
  • Fallback: International Distribution

Step 4: Edit Fields – Warehouse Format

{ "order_id": "ORD-12345", "customer_name": "Maria Garcia", "shipping_country": "US", "ship_speed": "Express", "total_value": 1250, "processing_deadline": "2026-07-02T10:30:00.000Z" }

Scenario 3: HR Employee Onboarding

Goal: Process new hire forms, check for security clearance requirements, route to the correct department, and send a personalized welcome email.

Form Trigger → If (Clearance Check) → Switch (Department) → Edit Fields (HR Format) → Email Node (Send Welcome)

Step 1: Trigger Data

{ "fullName": "James Wilson", "email": "jwilson@company.com", "department": "engineering", "position": "Senior Software Engineer", "role": "developer", "accessLevel": "high", "reportingManager": "Sarah Lee" }

Step 2: If Node – Security Clearance

  • Rule: If role = "admin" OR accessLevel = "high" → Needs Clearance
  • Else → Standard Onboarding

Step 3: Switch Node – Department

  • Rule 1: If department = "engineering" → Engineering Team
  • Rule 2: If department = "sales" → Sales Team
  • Rule 3: If department = "hr" → HR Team
  • Fallback: General Onboarding

Step 4: Edit Fields – HR Format

{ "employee_name": "James Wilson", "employee_email": "jwilson@company.com", "department": "engineering", "position_title": "Senior Software Engineer", "clearance_required": true, "onboarding_package": "Welcome James Wilson! Your start date is 2026-08-01..." }

How to See Which Switch Branch Executed

1. Visual Inspection

  • After running the workflow, click on the Switch node.
  • In the output panel, you'll see tabs: Output 0, Output 1, Output 2, etc.
  • The branch that contains data is the one that executed.
UI Note: Sometimes the Schema tab shows "No fields." Switch to Table or JSON view to see your data. This is a known display quirk.

2. Referencing a Specific Branch Later

If you need to use data from a specific branch in a later node, use the expression:

$("SwitchNodeName").all(branchIndex)
  • branchIndex starts at 0 (for Output 0).
  • Example: $("MyRouter").all(1) references data from Output 1.
Common Error: "No execution data available" — This happens when you try to reference a branch that wasn't executed for that item. Always verify your logic path.

What Comes After the Switch Node?

Once your Switch node has routed the data, you need to take action on each branch.

Option 1: HTTP Request Node

Send data to an external API — create a ticket in Zendesk, update a CRM record, post to Slack, etc.

Option 2: Email Node

Send a notification email to a team or user with the relevant data.

Option 3: Merge Node (Next Topic)

Combine data from multiple branches back into a single stream before sending it to a final destination.

Pro Tip: Always connect your Fallback output to an alert or logging node. This ensures unexpected data doesn't get lost and you're notified to update your rules.

Student Challenge

Build a "Product Review Moderation" Workflow that:

  1. Starts with a Form Trigger collecting: product name, rating (1-5), review text, and user email.
  2. Uses an If node to flag reviews with rating < 3 as "Needs Manager Review".
  3. Uses a Switch node to route reviews by product category: "electronics", "clothing", "books", and a fallback.
  4. Uses an Edit Fields node to format the output with:
    • review_summary combining product name and rating
    • moderation_status based on the If node
    • Only keep: product_name, review_summary, moderation_status, user_email

Quick Reference: When to Use Each Node

Node Best Used For Example
If Simple Yes/No decisions "Is the customer VIP?"
Switch 3+ distinct routing paths "Route to US, EU, or Asia center"
Edit Fields Data cleanup, formatting, renaming "Extract only name and email"
