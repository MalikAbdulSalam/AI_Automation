1. Understanding APIs

What is an API?

API (Application Programming Interface) is like a waiter in a restaurant:

  • You (the client) place an order (request)
  • The waiter (API) takes it to the kitchen (server)
  • The kitchen prepares your food (processes request)
  • The waiter brings it back to you (response)

3. Split Out Node

Purpose

The Split Out node breaks one large item into multiple smaller items.

Our Two Use Cases

For JSONPlaceholder (Direct Array):

Field To Split Out: $json
Include: No Other Fields

For NewsAPI (Nested Array):

Field To Split Out: articles
Include: All Other Fields

Why Different Settings?

APIData StructureSplit Out Field
JSONPlaceholderDirect array [{...}]$json
NewsAPIObject with array {"articles": [...]}articles

Example: NewsAPI Split Out

Input (1 item):

{
  "status": "ok",
  "totalResults": 35,
  "articles": [
    {"title": "Article 1", "description": "..."},
    {"title": "Article 2", "description": "..."}
  ]
}

Output (35 items):

Item 1: {"title": "Article 1", "description": "..."}
Item 2: {"title": "Article 2", "description": "..."}
...
Common Split Out Mistakes
  • Mistake: Splitting wrong field → Fix: Use articles for NewsAPI, $json for JSONPlaceholder
  • Mistake: Missing Include field → Fix: Set to "All Other Fields"
  • Mistake: Wrong field name → Fix: Check exact spelling (case-sensitive)

4. IF Node & Filter Node

IF Node vs Filter Node

FeatureFilter NodeIF Node
PurposeKeep matching itemsRoute to different branches
Outputs1 output (filtered)2 outputs (true/false)
Use CaseSimple filteringComplex routing

Project 1: JSONPlaceholder Filter

Using Filter Node:

Conditions:
  Field: body
  Operation: Length >
  Value: 100

Using IF Node:

Condition:
  Field: ={{ $json.body.length }}
  Operation: Number >
  Value: 100

Project 2: NewsAPI Filter

Using Filter Node:

Conditions:
  Field: description
  Operation: Length >
  Value: 100

Custom Expressions for Complex Filters

Keep articles with title containing "Apple" AND description > 100 chars:

={{ $json.title.includes("Apple") && $json.description.length > 100 }}

7. Creating Your Own API with Python

Why Create Your Own API?

  • ✅ Complete control over data
  • ✅ Security and privacy
  • ✅ Custom business logic
  • ✅ Integration with databases

Option A: FastAPI (Recommended)

Installation:

pip install fastapi uvicorn

Complete News API Clone:

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from typing import List, Optional
from datetime import datetime
import uvicorn

app = FastAPI(title="My News API", version="1.0")

# Data model
class Article(BaseModel):
    id: int
    title: str
    description: str
    content: str
    source: str
    publishedAt: str
    url: Optional[str] = None

# Sample data
sample_articles = [
    {
        "id": 1,
        "title": "First News Article",
        "description": "This is a sample news article description.",
        "content": "Full content of the first news article...",
        "source": "My News Source",
        "publishedAt": datetime.now().isoformat(),
        "url": "https://example.com/article1"
    },
    {
        "id": 2,
        "title": "Second News Article",
        "description": "Another sample news article description.",
        "content": "Full content of the second news article...",
        "source": "Another Source",
        "publishedAt": datetime.now().isoformat(),
        "url": "https://example.com/article2"
    }
]

# GET all articles
@app.get("/articles", response_model=List[Article])
async def get_articles():
    return sample_articles

# GET article by ID
@app.get("/articles/{article_id}")
async def get_article(article_id: int):
    for article in sample_articles:
        if article["id"] == article_id:
            return article
    raise HTTPException(status_code=404, detail="Article not found")

# GET search articles
@app.get("/search")
async def search_articles(q: str):
    results = [a for a in sample_articles if q.lower() in a["title"].lower()]
    return {"status": "ok", "totalResults": len(results), "articles": results}

# POST create article
@app.post("/articles", response_model=Article)
async def create_article(article: Article):
    new_article = article.dict()
    new_article["id"] = len(sample_articles) + 1
    sample_articles.append(new_article)
    return new_article

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)

Run the API:

python app.py

Test in Browser:

Option B: Flask (Simpler Alternative)

from flask import Flask, jsonify, request

app = Flask(__name__)

articles = [
    {"id": 1, "title": "First Article", "description": "Content..."},
    {"id": 2, "title": "Second Article", "description": "More content..."}
]

@app.route('/articles', methods=['GET'])
def get_articles():
    return jsonify(articles)

@app.route('/articles/', methods=['GET'])
def get_article(article_id):
    article = next((a for a in articles if a["id"] == article_id), None)
    if article:
        return jsonify(article)
    return jsonify({"error": "Not found"}), 404

if __name__ == '__main__':
    app.run(debug=True, host='0.0.0.0', port=8000)

8. Troubleshooting & Best Practices

Common Issues and Solutions

IssueSolution
Split Out not workingVerify field name: articles for NewsAPI, $json for JSONPlaceholder
IF node type errorUse ={{ $json.body.length }} with "Number >" operation
Email not sendingCheck SMTP settings, use app password for Gmail
API rate limitAdd delay between requests, use daily schedule
No items in outputCheck filter conditions, test with lower thresholds

Best Practices

1. Test Each Node Individually

  • Execute HTTP Request alone first
  • Check output at each step
  • Verify data structure

2. Handle Empty Results

// Add "No Op" node after IF node's false branch

3. Use Environment Variables

Store API keys in $vars or environment variables
Never hardcode credentials

4. Error Handling

// Add Error Trigger node
{
  "workflowId": "catch_errors",
  "error": "any"
}

5. Monitor API Limits

  • NewsAPI: 100 requests/day
  • Check usage regularly
  • Consider multiple API keys

Key Takeaways

  1. Always check API response structure before configuring nodes
  2. Split Out field must match the array name in response
  3. Use Filter Node for simple filtering, IF Node for complex routing
  4. Test incrementally — validate each node step by step
  5. Store API keys securely in environment variables
  6. Respect API rate limits — schedule workflows appropriately
