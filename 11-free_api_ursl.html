Retry Failed API Requests in n8n

This tutorial teaches students how to retry an API request automatically if it fails. Retrying failed requests makes workflows more reliable and is a common practice in production systems.

Learning Objectives

  • Understand why API requests fail.
  • Use the built-in Retry on Fail feature.
  • Create a manual retry workflow.
  • Use the Wait node.
  • Handle API failures gracefully.

Why Do APIs Fail?

Reason Example
Server Error 500 Internal Server Error
Rate Limit 429 Too Many Requests
Timeout Request Timed Out
Temporary Network Error Connection Lost
Instead of immediately stopping the workflow, we can retry the request.

Method 1 — Built-in Retry (Recommended)

Workflow

Schedule Trigger │ ▼ HTTP Request │ ▼ Continue Workflow

Steps

Step 1
  1. Add a Schedule Trigger.
  2. Add an HTTP Request node.
  3. Open the HTTP Request node.
  4. Go to Settings.
  5. Enable Retry On Fail.
  6. Set:
Max Tries = 3

Wait Between Tries = 5000 ms

Execution

Attempt 1 HTTP Request ``` │ ``` Success? ┌────────────┐ │ │ │Yes │No ▼ ▼ Continue Wait 5 Seconds ``` │ ▼ Attempt 2 │ Success? │ │ Yes No │ │ ▼ ▼ Continue Wait 5 Seconds │ ▼ Attempt 3 │ Success? │ Yes No │ │ ▼ ▼ Continue Workflow Failed ```
This method is the easiest and should be taught first.

Method 2 — Manual Retry Workflow

Workflow Diagram

Schedule Trigger │ ▼ HTTP Request │ ▼ IF ┌──┴───────┐ │ │ Success Failure │ │ ▼ ▼ Continue Wait 5 Seconds │ ▼ HTTP Request Retry │ ▼ IF

Step 1

Add a Schedule Trigger.

Step 2

Add an HTTP Request node.

Inside Settings enable

Continue On Fail = TRUE

This prevents the workflow from stopping.

Step 3

Add an IF node.

Check whether the API returned an error.

Example Expression 
{{$json.error}}
or 
{{$json.statusCode >= 400}}

Step 4

If API Failed

Add a Wait node. Configure 
Wait = 5 Seconds

Step 5

After Wait Add another HTTP Request node. Use exactly the same API settings.

Complete Workflow

Schedule Trigger │ ▼ HTTP Request #1 │ ▼ IF ┌───┴────┐ Success Failed │ │ │ Wait 5 sec │ │ │ ▼ │ HTTP Request #2 │ │ │ ▼ │ IF │ ┌──┴──┐ │ Success Failed │ │ │ │ │ Wait 5 sec │ │ │ │ │ ▼ │ │ HTTP Request #3 │ │ └──────┴────────► Continue

Real-Life Example

Suppose we call 
https://api.openweathermap.org/
Sometimes the API may return 
429 Too Many Requests
Instead of stopping Wait Retry Continue automatically.

Best Practices

Do Don't
Retry temporary failures. Retry invalid credentials.
Retry server errors. Retry bad requests (400).
Use a Wait node between retries. Retry endlessly.
Limit retries (3–5). Use 100 retries.

Classroom Exercise

Task

Build a workflow that:
  1. Runs every minute.
  2. Calls a public API.
  3. If successful, save the response to Google Sheets.
  4. If failed, wait 5 seconds.
  5. Retry up to 3 times.
  6. If all retries fail, send yourself a Gmail notification.

Homework

Create a workflow that:
  • Reads URLs from Google Sheets.
  • Calls each API.
  • Retries failed requests three times.
  • Stores successful responses.
  • Sends an email listing any URLs that still failed after all retries.

Summary

  • Retry makes workflows reliable.
  • Use the built-in Retry On Fail whenever possible.
  • Manual retries help understand workflow logic.
  • Always include a delay between retries.
  • Avoid retrying permanent errors such as 400 or 401.
